# 공개 데모 실행과 배포 안내

원본 문서의 실제 운영 도메인·계정·외부 서비스 설정은 제외했습니다. 아래는 현재 정적 데모의 실행 조건이며, 호스팅 계정에 적용된 설정이나 배포 완료를 뜻하지 않습니다.

## 실행 구조

저장소 루트의 HTML·CSS·JavaScript·이미지·폰트·샘플 JSON을 정적으로 제공합니다. 별도 빌드 단계와 서버 함수가 없으며 외부 서비스의 인증정보가 필요하지 않습니다.

문의폼은 브라우저에서 검증 후 데모 완료 메시지를 표시합니다. 통계 화면은 같은 출처의 샘플 JSON을 읽습니다. 원본 서비스 연동의 개발 설명은 [기술 구성](PROJECT.md#원본-코드에서-구현한-운영-연동)에 있습니다.

## 로컬 실행

```sh
python -m http.server 4173 --bind 127.0.0.1
```

- 홈: <http://127.0.0.1:4173/>
- 문의: <http://127.0.0.1:4173/contact/>
- 통계: <http://127.0.0.1:4173/dashboard/>

`file://`로 직접 열면 공통 HTML 로딩이 정상적으로 동작하지 않을 수 있습니다. Python 정적 서버만으로 모든 공개 데모 기능을 체험할 수 있습니다.

## 정적 호스팅 조건

- 저장소 루트를 정적 제공 디렉터리로 지정합니다.
- 별도 빌드 명령과 빌드 산출물을 요구하지 않습니다.
- `/about/` 등의 디렉터리 URL이 해당 `index.html`로 연결되어야 합니다.
- `partials/`, `dashboard/`, `assets/`, `fonts/`의 파일을 함께 제공합니다.
- 잘못된 경로에 대한 `404.html` 제공은 호스팅 서비스의 오류 페이지 설정을 확인합니다.

HTML·스크립트·CSS에 `/` 기준 경로가 있으므로 사이트 루트에서 제공해야 합니다. `https://사용자.github.io/저장소명/` 형태의 GitHub Pages 프로젝트 하위 경로는 현재 구성으로 지원하지 않습니다. 지원하려면 페이지 링크뿐 아니라 공통 HTML·샘플 JSON·이미지·스타일·폰트 요청 경로를 함께 조정해야 합니다.

## 배포 전 확인

1. [정적 검사와 화면 확인](MAINTENANCE.md#검사)을 진행합니다.
2. 회사 자료·실제 개인정보·운영 식별자·인증정보가 추가되지 않았는지 변경 파일을 검토합니다.
3. 문의와 통계가 데모임을 화면과 README에서 명확하게 안내하는지 확인합니다.
4. 폰트 라이선스와 사용 자료의 권리를 확인합니다.

배포 후에는 홈, 각 소개 페이지, 문의·통계, 모바일 메뉴, 공통 푸터, 이미지·폰트와 오류 페이지를 확인합니다. 브라우저 Network에서 실제 문의 전송이나 분석 서비스 호출이 없는지 확인합니다.

## 운영 서비스로 전환할 때

이 공개 데모의 클라이언트 검증은 실제 서버 처리의 검증을 대신하지 않습니다. 실제 서비스를 구축한다면 서버 검증·인증정보 관리·봇 방어·개인정보 처리·관리자 접근 보호를 별도로 구현하고 검증해야 합니다. 검색 제외 설정은 접근 제한 수단이 아닙니다.

현재 데모는 문의 데이터를 보관하거나 이메일로 전송하지 않습니다. 호스팅 제공자가 기본 접속 로그를 처리할 수 있으므로 실제 배포 환경에 맞게 개인정보 안내를 확인합니다.
