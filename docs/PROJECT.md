# 기술 구성과 개발 내용

이 문서는 원본 프로젝트의 기술 설명을 회사 식별정보 없이 정리한 문서입니다. **원본 코드의 구현 경험**과 **현재 공개 데모의 실행 범위**를 구분합니다. 실제 배포 상태나 외부 서비스의 운영 검증 결과를 의미하지 않습니다.

## 현재 공개 데모의 흐름

```text
브라우저 → 페이지 HTML + 공통 CSS·JavaScript
         → 공통 푸터 HTML
문의폼   → 브라우저 입력 검증 → 데모 완료 안내
대시보드 → 기간별 샘플 JSON → 차트·표 렌더링
```

별도 프레임워크, 빌드 단계, 서버 함수가 없는 정적 다중 페이지 구성입니다.

| 페이지 | 역할 |
| --- | --- |
| `/` | 브랜드 소개와 데모 진입 |
| `/about/` | 가상 브랜드 소개 |
| `/services/` | 예시 서비스 소개 |
| `/process/` | 데모의 사용자 흐름 |
| `/facility/` | 공간 소개용 예시 레이아웃 |
| `/contact/` | 입력 검증과 파일 선택 체험 |
| `/privacy/` | 데모 입력값·파일 처리 안내 |
| `/dashboard/` | 샘플 통계 화면 |

## 공통 UI와 반응형 구성

페이지별 HTML에 Header와 상단 메뉴가 있고, [공통 스타일](../styles.css)과 [공통 스크립트](../app.js)를 사용합니다. 푸터는 [HTML partial](../partials/footer.html)을 `data-include="footer"`로 불러옵니다. 연도와 현재 페이지 표시를 갱신하며, 로드 실패 시 대체 링크를 제공합니다.

메뉴 변경은 각 페이지의 Header와 공통 푸터를 함께 수정해야 합니다. Header 전체를 동적으로 생성하는 구조는 아닙니다.

주요 이미지·설명 영역은 데스크톱에서 2단, 모바일에서 1단으로 표시합니다. 대시보드는 별도의 [스타일](../dashboard/styles.css)을 사용하며 좁은 화면에서 검색 성과 표를 항목별로 읽기 쉽게 전환합니다. CSS 분기점이 존재한다는 사실과 모든 화면 폭의 검수를 완료했다는 주장은 구분합니다.

## 문의 입력 경험

[문의 화면](../contact/index.html)은 `novalidate`를 사용하며 JavaScript로 필드별 안내를 제공합니다.

- 필수값, 최대 길이, 이메일과 국내 휴대전화·지역번호 형식을 확인합니다.
- 필드를 벗어나면 검증하고, 오류가 있는 필드를 수정하면 안내를 갱신합니다.
- 제출 시 첫 번째 오류 항목에 포커스를 이동합니다.
- 파일 선택·삭제·드래그 앤 드롭과 파일명·크기·전체 용량 표시를 지원합니다.
- 최대 3개, 파일당 10MB, 총 20MB, 허용 확장자와 동일 파일 중복 여부를 확인합니다.
- 데모 확인 체크박스가 선택되어야 완료할 수 있습니다.

완료 시 입력과 파일 선택을 초기화합니다. **서버 업로드·이메일 전송·브라우저 저장소 기록은 하지 않습니다.** 파일 형식 검사는 데모의 선택 경험을 위한 것으로, 실제 서버 업로드의 보안 검증을 대신하지 않습니다.

## 통계 화면

[대시보드 스크립트](../dashboard/app.js)는 `sample-7.json`, `sample-30.json`, `sample-90.json`을 읽습니다. 기본 기간은 30일이며, 방문자·검색 유입·문의 지표를 전환할 수 있습니다. 샘플 날짜는 고정되어 있고 실시간 운영 통계가 아닙니다.

SVG로 추이를 표시하고, CSS의 원뿔형 그라디언트로 유입 경로를 표시합니다. 요약 지표, 인기 페이지, 검색어, 검색 페이지 성과, 문의 전환율을 함께 렌더링합니다.

새 기간을 요청할 때 기존 요청을 `AbortController`로 취소합니다. 현재 요청과 응답의 관계도 확인해 이전 응답이 새 화면을 덮어쓰지 않도록 합니다. 로딩, 빈 데이터, 일부 오류와 전체 실패를 구분합니다. 샘플 데이터는 정상 상태를 제공하며 오류 처리 코드는 스크립트에서 확인할 수 있습니다.

## 원본 코드에서 구현한 운영 연동

아래는 원본 개발 경험의 설명입니다. 해당 서버 코드·키·실제 데이터는 공개 저장소에 포함하지 않습니다.

| 영역 | 원본 구현 | 공개 데모 |
| --- | --- | --- |
| 호스팅 | Cloudflare Pages와 서버 함수 구성 | 정적 파일만 실행 |
| 봇 확인 | Turnstile 서버 검증 및 검증된 호스트 확인 | 외부 위젯 제외 |
| 문의 전송 | 서버 입력 검증 후 Resend 이메일 전송 | 브라우저 검증 후 데모 안내 |
| 분석 | GA4 방문·문의 이벤트 및 Data API 조회 | 가상 통계 JSON |
| 검색 성과 | Google Search Console API 조회 | 가상 검색어·수치 |
| 인증정보 | 서버 환경변수에서 비밀값 읽기 | 인증정보와 서버 연동 제외 |

원본 문의 처리에서는 POST, 동일 출처, HTTPS 또는 로컬 환경, 요청 크기를 확인하고 **`multipart/form-data`**로 입력과 첨부파일을 읽습니다. 허용 필드·선택값·필수값·길이·연락처·동의·첨부 제한을 서버에서 재검증하고 봇 확인이 성공한 뒤 이메일을 전송합니다. HTML 이메일의 사용자 입력은 이스케이프합니다.

원본 클라이언트의 전송 제한은 **90초**이고 이메일 서비스 요청 제한은 **60초**입니다. 전송 중 중복 제출을 막고, 실패 시 입력을 유지하며, 성공 시 폼을 초기화하고 문의 이벤트를 기록합니다. 요청 본문은 multipart이고 성공·오류 응답은 JSON입니다.

원본 통계 처리에서는 서버의 Google 서비스 계정으로 읽기 API를 호출하고 기간별 지표를 화면용 데이터로 변환합니다. 한국 시간 기준 전일까지와 이전 동일 기간을 비교하며, 한 서비스가 실패해도 가능한 데이터를 반환합니다. 브라우저에 서비스 계정 비밀값을 넣지 않는 방식입니다.

운영 도메인, 계정 식별자, 환경변수의 실제 값, 문의 수신 주소, 실제 통계, 접근 정책 상태는 문서에 포함하지 않습니다.

## 접근성과 검증

본문 바로가기, label, 오류를 연결하는 `aria-describedby`, `aria-invalid`, `aria-live`, 메뉴 상태와 키보드 조작을 적용했습니다. 모션 감소 설정을 존중하며 파일명은 `textContent`로 표시합니다.

현재 재실행 가능한 정적 검사는 [check_demo.py](../check_demo.py)입니다. 검사 범위와 수동 확인 절차는 [유지보수 안내](MAINTENANCE.md)에 있습니다. 브라우저 검사 이력은 [README](../README.md#검증한-내용)에 정리했습니다. 성능 개선 수치나 모든 브라우저의 검증 결과를 주장하지 않습니다.
